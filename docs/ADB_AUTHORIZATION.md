# 通话初始化失败：缺少 QADBKEY 授权

## 问题与实机观察

DJOneHub v1.2.10、第一代 DJI 4G 模块、`QDC507GLEFM21` 固件，在启用通话支持后可能出现：

```text
通话支持未验证，已恢复原始模块配置
USB ADB interface (6/adb) not found on 2c7c:0125
```

本次报告中，原始查询结果为：

```text
+QCFG: "usbcfg",0x2CA3,0x4006,1,1,1,1,1,0,1
```

用户手动完成 `QADBKEY` 授权，再保留 DJI VID/PID 将七个接口标志全部设为 `1`，回读确认并重启后，已实际通话成功。没有刷写固件。

这是该设备上的观察结果，不表示所有相似报错都由授权缺失引起。[Issue #9](https://github.com/rogerbush007-a11y/DJOneHub-mac-enhanced/issues/9) 报告了相似现象；[PR #12](https://github.com/rogerbush007-a11y/DJOneHub-mac-enhanced/pull/12) 处理的是授权完成之后的通话期 ADB 会话问题，与本补丁不同。

## 代码原因

- 原初始化流程未执行 `AT+QADBKEY?` / `AT+QADBKEY="…"`。
- 原 `isCallAudioCapable()` 接受 Quectel 标识下的 `1,1,1,1,1,0,1`。但语音路由需要通过 ADB 部署并启动模块侧组件，仅有 UAC 不够。
- 因此，即使 USB 配置写入返回 `OK`、ADB 位却仍为 `0`，旧流程也可能继续重启，直到路由验证失败才回滚。

## 本补丁行为

1. 仍只在用户明确确认“启用通话支持”并成功保存 USB 配置备份后执行修改。状态查询不会授权设备。
2. ADB 位为 `0` 时，读取授权挑战，只接受已知的八位十进制数字格式，计算旧版授权响应并要求模块返回 `OK`。
3. 未知格式、拒绝或超时：停止，不写 USB 配置、不重启；不猜测其他固件协议。
4. 保留现有的 DJI / Quectel VID/PID；对于其他工具留下的未知标识，保留原来转换为受支持 Quectel 标识的恢复行为。
5. 写入 ADB + UAC 配置，必须回读到完整目标配置及 `OK`，不再接受 ADB 位仍为 `0`。
6. 已具备完整配置的设备不重复授权或改写 USB；后续 IMS、重启及路由验证/回滚流程保持不变。

## 授权算法与隐私

旧版协议计算方式是 `MD5-crypt("SH_adb_quectel", challenge)` 的校验串前 15 个字符。实现不启动外部命令、不增加 Go 依赖；MD5 仅用于兼容模块协议，不用于应用密码存储。

协议参考：[公开 QADBKEY 算法](https://github.com/carp4/qadbkey-unlock/blob/cab52a0a7429c8d8b8f31da8894c8c93155c0fc5/qadbkey-unlock2.py)。实现使用独立 OpenSSL 结果作为合成测试向量。

- 自动授权使用直接 USB AT 通道；串口管理器在超时时可能记录命令，即使使用 Silent 接口也不安全，因此此补丁不通过该通道自动发送授权命令。
- 授权错误不向状态、日志返回原始响应或传输错误，以免回显包含设备挑战或密钥。
- ADB 调试授权可能持久保存。USB 配置备份和回滚不负责撤销授权；确认弹窗已说明这一点。仅连接可信电脑。
- 提交中没有实际设备挑战、授权密钥、SIM 标识、电话号码、运行日志或用户截图。测试数据均为合成值。

## 验证与限制

自动测试覆盖已知算法向量、非法挑战、授权前后命令顺序、DJI/Quectel 标识保持、已有 ADB 的跳过行为、授权失败停止、响应不完整、ADB 位未生效及错误脱敏。

实机已验证的是用户手动执行的授权/配置/重启步骤和最终成功通话；新的一键授权代码尚未在未授权实机上端到端验证。为避免破坏当前可用状态，没有重新锁定或重启用户模块。

建议维护者使用尚未授权的测试模块验证：启用前备份 → 确认授权 → 回读七个 `1` → 重启后枚举到 ADB → 路由验证 → 实际双向通话，并检查失败路径没有泄露挑战或密钥。

本补丁只支持已观察到的旧版八位数字授权协议，不承诺兼容其他 QADBKEY 格式，也不解决运营商 IMS 注册、麦克风权限或通话期 ADB 会话超时等其他问题。
